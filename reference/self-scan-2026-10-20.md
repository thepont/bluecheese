# Bluecheese self-scan — 2026-10-20

The source findings remain **unreviewed candidates**, not confirmed false positives.
An exhaustive Rust match is not automatically a design problem, but repeated language
selection can scatter knowledge about language grammars. The detector recognises
syntax; it does not establish that changes are difficult or that refactoring is warranted.

## Follow-up: verified refactoring

The three language-dispatch matches reviewed above were removed in commits
`3f37849` and `c080d6b`. Comment recognition and accessor-chain analysis now
come from the existing LanguageModel implementations. The chain algorithms moved
into the language subsystem; detectors no longer choose those algorithms by LanguageId.
This is a behaviour-preserving refactoring, with no detector test changes or suppressions.

Before editing, all 24 focused comments, message-chain and Java parity tests passed.
They passed unchanged after the move. A broader run passed 178 tests with the known
source-cleanliness test filtered out; running that test separately still failed,
now reporting data clumps from the expanding Rust support. The source switch scan
confirmed that the three reviewed locations are gone; other detector matches remain.
Source and detector ports were changing concurrently, so the original frozen-snapshot
inventory below remains a historical record rather than the current project inventory.

Changed Rust files pass rustfmt checks and the diff passes whitespace checks.
Strict Clippy remains red: ten diagnostics in untouched detector code (collapsible
conditions, identical branches and a while-let suggestion). No diagnostic named a
file changed by this refactoring. An initial broader build exhausted disk quota;
clearing an earlier disposable build cache allowed the 178-test run to complete.

## Why these are not established false positives

| Snapshot location | Observation | Assessment |
| --- | --- | --- |
| src/detectors/message_chains.rs:55,65 | Two exhaustive LanguageId dispatches choose a chain-depth algorithm and a call-expression grammar name. | Legitimate dispatch is plausible; repeated language policy may also warrant consolidation. Unreviewed. |
| src/detectors/comments.rs:82 | LanguageId selects grammar comment-node names; Java and Rust share one result. | Could remain a small explicit match or belong in the language model. Unreviewed. |
| tests/loading.rs:64 | Result match extracts an expected error and panics on unexpected success. | A normal test assertion idiom; a strong candidate for an accepted intentional use, but no suppression was applied. |
| tests/parity.rs:38 | assert_parity takes four string arguments: corpus, golden name, smell, Java smell. | A threshold hit; review whether those values form a useful parameter object or whether the helper is already clear. Unreviewed. |

The comments rule flags more than five words or TODO. It does not determine whether
a comment compensates for unclear code. For example, src/detectors/comments.rs:1 is
the module documentation explaining the rule itself. That is evidence that this
heuristic is broad, not evidence that every comment finding is harmless. Review the
content and the code it explains before accepting or rejecting each finding.

## Ignoring intentional examples

Existing path exclusions can omit authored fixtures and probes while retaining test code:

```sh
cargo run --locked -- -f . -s switch-stmts -x tests/fixtures/ -x reference/java-probes/
```

Use `-x tests/ -x reference/` for the implementation-and-examples scope.
No source finding was automatically ignored merely because we wrote it. Individual
finding suppressions are not currently implemented; path filters hide whole paths.
No analyser behaviour, tests, or exclusions were changed for this report.

## Coverage and validation limits

In this snapshot, several detectors still depend on Java-specific models. In
particular Rust has no shotgun call-resolution implementation, so its zero shotgun
result is not evidence against shotgun surgery. This scan does not analyse git-log
co-change. The cross-language duplicate detector cannot find duplicates within an
all-Rust scope; its zero there is not evidence of no duplication.

The frozen snapshot's `cargo test --locked --test self_check` completed with
**1 passed, 1 failed**. The failing test is
`the_projects_own_source_is_free_of_every_smell_the_tool_can_detect`; the expanded
comments detector reports source comments. This failure was observed before this
documentation change and was left visible. The full test suite was not run for this
report-only change. Earlier partial scans were discarded; the totals above come from
the completed frozen-snapshot run.
